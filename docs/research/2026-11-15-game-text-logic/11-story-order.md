# 劇情檔的順序

2026-11-19。依據是遊戲的**靜態資料包**（2026-11-12 版，Addressables 的 `static_s1` bundle，沒有加密，內容是 2,229 個 JSON），對照 `raw-20261112` 的 1,001 個 `StoryData` 檔。讀法與重新產生的步驟見 [method/README.md](method/README.md) 的「劇情檔的順序」。

「確認」＝直接從資料讀到；「推定」＝有依據但資料沒有直接寫。

## 先講結論

- 劇情檔名就是劇情代號（`StoryData/<代號>.json`，[01](01-custom-language.md)）。代號的先後**不能只看檔名**：同一個節點是 `B → I → A`（戰前 → 戰鬥中 → 戰後），照字母排剛好相反；迷宮（`<n>D…`）接在該章的 `S` 之後，第 8 章的在中間；第 10 章不照編號。
- 1,001 個檔裡，950 個的位置資料直接有寫（確認），50 個是照檔名插進同一章的（推定），1 個（`RPG1`）沒有依據。
- 這份順序寫成 `rules/story-order.yaml`，網頁同一類別裡的檔照它排（`internal/site/order.go`）。

## 資料在哪裡

| 資料 | 內容 | 涵蓋 |
|---|---|---|
| `storytheater-main-*`（13 個檔） | 劇情劇場的主線：每筆是一章（`chapterId`、`subChapterId`），底下 `storyList` 逐筆列出 `storyId`、`nodeId`、`stageDetail`（`Before`／`Inter`／`After`） | 443 個檔 |
| `storytheater-other-*`（24 個檔） | 劇情劇場的其他劇情（插曲、活動、小故事）：多一個 `sortingOrder` | 224 個檔 |
| `storytheater-personality-<角色>`（12 個檔） | 人格故事：`characterId` → 每個人格（`personalityId`、`releaseDay`）→ `personalityStoryList` 的 `storyId` | 184 個檔 |
| `story-loading-cg.json`、`story-loading-cg-110.json` | 載入設定：每筆是一章或一個活動，`storyIds` 逐筆列出代號；`uiConfigFormerIdForOrder` 記著「排在哪一筆之後」 | 759 個檔，其中 99 個劇場清單沒有 |
| `storybattle-*`、`abbattle-*` | 關卡資料：每個關卡的 `story.enter`、`story.exit` 與戰鬥中播放的代號 | 沒有用來排序，只用來確認 `PC…` 屬於巡禮 |

類別宣告（`StageStoryTheaterDataBase`、`StoryTheaterInfo`、`PersonalityStoryTheaterData`、`StoryTheaterPersonalityInfo`）的欄位和 JSON 的鍵一致（確認）。

載入設定的順序和劇場清單**完全一致**（兩邊都有的 660 個代號，相對順序沒有任何一組相反；確認），所以劇場清單沒有的代號可以照它在載入設定裡的位置插入。

## 字尾的意思

劇場清單每筆的 `stageDetail` 對字尾（確認）：

| 字尾 | `Before` | `Inter` | `After` |
|---|---|---|---|
| `B` | 362 | | 100 |
| `A` | 1 | | 171 |
| `I` | | 7 | |
| `X`（小故事） | 2 | 2 | 2 |

- `B` 是戰前（Before）、`A` 是戰後（After）、`I` 是戰鬥中（Inter）。同一個節點有兩個以上的檔時，清單裡一律是 `B → I → A`（例：`S926B`、`S926I1`、`S926I2`、`S926A`）。
- 字尾不完全可靠：有 100 個 `B` 檔標的是 After（那個節點只有一段劇情、在戰後播），所以「戰前還是戰後」要看 `stageDetail`，不要看檔名。
- 有編號的 `I`（`I1`、`I2`…或 `I`、`I2`…）照編號。`C` 只在第 10 章出現（`S1042C`～`S1048C`），意思沒有資料。

## 順序

### 主線（`S…` 與 `<n>D…`）

- 章的先後照 `subChapterId`（100 序章、101～110 第 1～10 章）；第 9 章分三個檔（`a1c9p1`～`p3`），照檔名接起來。
- 章內照清單。第 1～9 章的 `S` 檔，清單順序和「編號小的在前，同編號 `B → I → A`」完全相同（確認，0 個例外）。
- 迷宮 `<n>D…`（確認）：

  | 章 | 迷宮的位置 |
  |---|---|
  | 1、2、3、4、5、7 | 全章 `S` 之後（例：第 1 章 `S111B` 之後是 `1D101A`…`1D306A`） |
  | 8 | 在中間：`S820B` 之後、`S821B` 之前 |
  | 6、9、10 | 沒有迷宮檔 |

- 第 10 章是 RPG 式流程，劇場清單只逐筆列了 4 個代號（開頭的 `S1003B`、`S1004B`、`S1005B` 與最後的 `S1044B`），中間以樓層分組。載入設定列了 56 個，順序**不照編號**：`S1003B`～`S1005B` 在 `S1001B` 之前；`S1060B`～`S1062B`、`S9991B` 在 `S1016B` 與 `S1017B` 之間；`S9992B` 在 `S1029B` 與 `S1030B` 之間；`S1045C`～`S1048C` 在 `S1042B` 之後；`S1044B` 最後。這份順序在其他章都和劇場清單一致，所以第 10 章也照它（確認的是「資料這樣列」，實際遊玩時三條路線 a、b、c 是否照這個先後沒有另外驗證）。

### 插曲、活動、小故事（`E…`、`ES…`）

- 組的先後照 `sortingOrder`（確認）。小故事（`E0xxX`，`subChapterId` 90xx）穿插在插曲與活動（91xx）之間：

  `9103`（`E3xx`）→ `9010`（`E010X`～`E030X`）→ `9104`（`E4xx`）→ `9011`（`E041X`、`E042X`）→ `9012` → `9105`（`E501`～`E509`）→ `9013` → `9014` → `9107`（`E510`～`E519`）→ `9015` → `9016` → `9109` → `9017` → `9110` → `9018` → `9019` → `9114` → `9116` → `9020` → `9119`（`E8xx` 與 `ES…`）→ `9021` → `9125` → `9127` → `9022`

- 組內照清單。`E` 檔和主線一樣是編號、`B → I → A`。
- `ES…`（35 個檔）全部在 `9119` 裡，夾在 `E803B` 與 `E805B` 之間，而且**不照編號**：`ES013` 在 `ES012` 之前，`ES061` 在 `ES030` 之前。
- 載入設定的 `uiConfigFormerIdForOrder` 把主線和活動串成一條：100 → 101 → 102 → 103 → 9103 → 9010 → 104 → 9104 → 9011 → 105 → 9012 → 9105 → … → 109 → 9123 → 9125 → 9127 → 110。也就是主線各章與活動的時間先後。網頁把主線和插曲分成兩個類別，所以沒有用到這條鏈。

### 人格故事（`P#####`）

先 `characterId`（1～12），再照人格在清單裡的順序，結果和代號的數字順序相同（確認）。每筆另有一個 `order`（1～11），用途沒有查。

## 和網頁排序的比較

改之前，網頁在同一個類別裡照檔名自然排序。和上面的順序比：

| 範圍 | 改之前 | 遊戲 |
|---|---|---|
| 同一節點 | `A → B → I` | `B → I → A` |
| 迷宮 | 所有 `<n>D…` 排在所有 `S…` 之前 | 接在該章的 `S` 之後（第 8 章在中間） |
| 第 10 章 | 照編號 | 不照編號（見上） |
| 小故事 `E0xxX` | 全部在插曲之前 | 穿插在插曲之間 |
| `ES…` | 所有 `E…` 之後，照編號 | 在 `E803B` 與 `E805B` 之間，不照編號 |
| 主線各章的先後、人格故事 | 照編號 | 相同 |

數字：主線在劇場清單裡的 443 個檔，照遊戲順序相鄰的兩個檔，有 86 組在改之前的網頁上是反過來的。

改之後：

- `rules/story-order.yaml` 列出 1,000 個檔，分 49 組（主線 11、活動 25、巡禮 1、人格故事 12；活動裡的 `other-0` 是沒有位置資料的 `E00x`）。推定的檔在該行後面標 `# 推定`。
- 網頁先照類別（`guides/routing.yaml` 的 `priority`），同一類別裡表上有的檔照表，表上沒有的排在後面、照檔名。所以遊戲新增、而表還沒重新產生的檔會暫時排在該類別的最後。
- 這個順序用在「上一個／下一個檔」、目錄裡同一層的檔、更新頁的排列。目錄的分群樹仍然把 `S` 與 `D` 分成兩支（分群照檔名開頭，`guides/routing.yaml`），所以「迷宮接在該章之後」只在上一個／下一個檔看得到。
- 類別沒有變：主線與迷宮在 `story-main`，`E`／`ES`／`PC` 在 `story-interlude`，`P` 在 `identity`。主線與活動之間的時間先後（上面那條鏈）沒有反映在網頁上。
