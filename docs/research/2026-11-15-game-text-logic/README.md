## 各題的短答

### 1. 自訂語言的整體處理

- 遊戲讀 `LimbusCompany_Data/Lang/config.json` 的 `lang`，用 `Lang/<lang>/` 當語言包。**一定要有可用的字型（小寫 `.ttf`／`.otf`）才生效**，沒有字型時文字也不會被讀。
- **文字的底固定是英文**，不管遊戲內選什麼語言。語言包缺的檔案或 id 顯示英文；英文也沒有的顯示 `Unknown`。
- 要讀哪些檔由官方的檔案清單決定，檔名是官方檔名去掉 `KR_`。語言包不能新增檔案。
- 一般文字表以 **id 為單位整筆取代**英文的條目：語言包的條目少了欄位，那個欄位就是預設值（多半是 `Unknown`），不會拿英文補。語音、播報員、歌詞、劇情是**整個檔取代**。
- 語言包的 JSON 格式錯誤沒有保護，會讓整張表（連英文的底）都載不進來。
- 劇情檔的每一列依位置與遊戲內的演出配對，列數與順序必須與官方相同。
- 版面、字級、圖片照遊戲內選的語言（KR／EN／JP），自訂語言沒有自己的分支。

### 2. `<ruby>` 等標籤

- `<ruby>` **只在三個地方有效**：劇情對話（`StoryData` 的 `content`）、劇情紀錄、劇情字幕（含在劇情裡顯示的 `BgmLyrics`）。其他地方（說話者名稱、稱號、地點、戰鬥台詞、語音、技能、介面……）會原樣顯示成文字。
- 只能寫 `<ruby=注音>本文</ruby>`。注音裡不能有 `>`（不能放標籤），不能巢狀，`=` 不能省，必須小寫。
- 一般的 TextMeshPro 標籤（`<color>`、`<size>`、`<b>`、`<style>`、`<noparse>`……）到處都能用，沒有任何程式把它關掉。`<style>` 的名稱必須是官方用過的。
- `<style="highlight">`、`<style="upgradeHighlight">` 是以完全相同的字串比對的，寫法要逐字相同。

### 3. 關鍵字、`<noparse>`、`[TabExplain]`

- **只有這些欄位會處理關鍵字**：技能與硬幣的說明、被動的說明與摘要（標籤、`[ID]`、名稱三種都處理）；E.G.O 飾品的 `desc`／`simpleDesc`、`PanicInfo` 的說明（只處理 `[ID]` 與名稱，不處理標籤）。其他欄位寫 `[Laceration]` 會原樣顯示。
- **純文字名稱變成關鍵字的條件**：名稱（語言包 `Bufs*.json` 的 `name`）後面緊接「文字結尾、空白、數字、或 `・「」『』.,/&;`」。全形標點、中文字、`)`、`<`、`[` 都不會觸發。長的名稱優先。
- **`<noparse>名稱</noparse>`**：因為名稱後面變成 `<` 而不觸發。有連結處理的欄位都有效。裡面不可以放 `[ID]`。
- **`名稱[TabExplain]`**：因為名稱後面變成 `[` 而不觸發；`[TabExplain]` 本身是 `SkillTag.json` 裡文字為空的標籤，所以會消失。**只在技能、硬幣、被動的文字有效**；在飾品 `desc` 會原樣顯示。`[` 前面不能有空格。
- 另外兩個官方機制：`Bufs*.json` 條目上的 `"excludeAutoLink": true`（這個名稱完全不自動連結，是各語言自己設定的；日文官方多標了「～」「始」「種」），以及名稱前後緊鄰 U+200B。
- 技能、被動文字裡，不是狀態 id 也不是 `SkillTag.json` id 的 `[xxx]` 會顯示成 `Unknown`。

### 4. 其他要注意的

- `{0}`、`{1}` 的集合要與 KR 相同，不能有其他的 `{`、`}`；不少地方沒有錯誤保護。
- 選擇事件的文字以 `\n\n` 分頁；自訂語言的頁數比官方少時，遊戲會自動補上內容為 `...` 的頁。
- `ChoiceEventEffect*.content` 的文字會被當成正規表示式編譯，半形括號不成對會出錯；`{reward}` 這類名稱拼錯會整個消失。
- 劇情 `content` 裡 `//` 之後的文字會被丟掉；`model` 不可以翻譯。
- 稱號裡的 `\n` 在單行顯示時變成半形空格；罪孽型敵人名字裡的半形 `?` 個數有意義。
- 陣列長度、數值、布林等結構欄位要與 KR 相同。

### 5. 戰鬥氣泡文字（2026-11-16 補充）

- `BattleSpeechBubbleDlg*.json` 只有 `dlg` 會顯示；`desc` 是開發者註記，`id` 是語音事件的名稱。
- 文字**原樣**送上畫面，整句一次出現：沒有 `{0}`、沒有去頭尾空白、沒有關鍵字、沒有 ruby。可以用 `<i>`、`<color>`、`<size>`。
- 顯示在三種元件：角色頭上的氣泡（絕大多數）、畫面中央字幕（一場頭目戰）、演出時畫面下方／中間的字幕。
- **顯示時間與文字長度無關**：語音長度（最少 3 秒），沒有語音的腳本台詞固定 6 秒。同一個單位的新句子直接蓋掉舊的。
- 氣泡的寬度、自動換行、字級都是 prefab 的設定，讀不到；程式不插入換行，譯文能決定的換行只有 `\n`（官方各語言的 `\n` 數量本來就不一致）。官方 CJK 最長 111 字。
- `dlg` 是空字串時這句話會消失；腳本直接取用的十個 id 則會出現 6 秒的空氣泡框。這份文字不會出現 `Unknown`。
- `PersonalityVoiceDlg` 的戰鬥語音台詞（擊殺、混亂、死亡等）用同一個氣泡，規則相同。

### 6. 族群（分類）需不需要調整（2026-11-16 補充）

- 不需要重劃。遊戲依資料表分（77 份清單對 77 張表），專案依內容與語氣分，目的不同；依欄位的檢查也不看族群。
- 放錯的檔案：`Skills.json`（258 筆罪人技能，卻在 `enemy`）、`Passive-*` 與三個 `Passives-*`（敵人的被動，卻在 `ally`）、`Passives_fools`、`ChoiceEventKeyword`。除了三個 `Passives-*`（節點分不開），已在同日改好 `guides/routing.yaml`。
- 技能、被動在遊戲裡各只有一張表，卻分在 `ally` 與 `enemy`；「不一致的譯法」只在族群內比，所以有 43 句同欄位、同 KR、跨族群譯法不同的句子目前看不到。建議加跨族群的比較，而不是合併族群（已做成警告 `cross-group`）。
- 戰鬥氣泡有一半是敵人與 NPC 的台詞，建議在 `identity` 的指引補說明。
- 有一批已翻譯的單位在遊戲不讀的欄位裡，見下一題。

### 7. 各欄位什麼時候顯示（2026-11-16 補充）

- 硬幣、被動、狀態的 `summary` 與飾品的 `simpleDesc` 是「短說明」，**只在戰鬥中單位執行技能時的技能面板出現**；其他地方一律用 `desc`。被動、狀態、飾品的短說明只有異想體戰才顯示，一般戰鬥只列名稱。
- 硬幣的 `summary` 會套用完整的關鍵字處理；空的時候改用 `desc`。狀態的 `summary`「沒有這個 key」會改用 `desc`，「空字串」只顯示名稱。
- 狀態圖示的提示框與人格資訊用 `Bufs*`；點關鍵字連結的說明用 `BattleKeywords*`。
- 劇情的名稱與稱號各自決定：列上的 `teller`、`title` 有寫就用，空的才查 `ScenarioModelCodes*`。大部分的名稱與稱號其實來自 `ScenarioModelCodes*`。
- `PersonalityVoiceDlg` 的 `desc` 會顯示（語音清單每一格的標題）；`EGOVoiceDig` 與 `BattleSpeechBubbleDlg` 的 `desc` 不會。
- **約 3,340 個已翻譯的單位在遊戲不顯示的欄位裡**：`Enemies*`／`Assist*` 的 `desc`（1,277）、`EGOVoiceDig` 的 `desc`（335）、`BattleKeywords*` 的 `summary`（236）、`Personalities*` 的 `desc`（208）與 `nameWithTitle`（207）、`StageNode*` 的 `place`（208）、`AbnormalityGuides*` 的 `clue`（183）、`ActionEvents*` 的 `name`（171）、`AbEvents*` 的 `title`（170）、`AbDlg_*` 的 `teller`（169）、`Egos*` 的 `desc`（122）等。

### 8. `{0}` 代入的是什麼（2026-11-18 補充）

- 絕大多數是 `string.Format`：索引可以調換、重複，但超出範圍或多一個大括號會出錯。索引的集合照 KR。
- 數字幾乎都是沒有正負號、千分位、單位的整數；`%`、`+`、量詞寫在範本裡。
- 例外：狀態能力約 43 個範本的數值**已經帶正負號**（不要再寫 `+`）；十來個介面字串與 `{reward}` 的值**已經包好顏色**；日期、「道具名 數量」等是**組好的整段文字**。
- 代入的名稱是已經翻好的譯名，不含括號、顏色與人格稱號。
- 同一個索引不一定是同一種東西：鏡牢起始增益的 `{1}` 可能是狀態名稱，也可能是數字。
- 狀態說明：`{0}` 強度、`{1}` 回數、`{2}` 累計消耗的回數；`summary` 的索引個數會決定 `desc` 拿到幾個參數。
- 選擇事件結果的具名記號只認 8 個名稱，拼錯的整個消失。
- 個人檔案問候語的 `{0}` 是玩家另外挑的詞，任何詞都可能進任何句子。

### 9. 程式拼接的句子（2026-11-18 補充）

- 人格全名是「稱號＋半形空格＋名字」；狀態名稱後面會接「空格＋層數」；標籤後面會接「空格或冒號＋數值」。名稱與標籤的頭尾不要有空格或冒號。
- 程式會自己加的符號不要再寫：空格、冒號、方括號、半形括號、`%`、`+`、`x`、條列符號。
- 日期、時區、星期全由程式產生；時區跟著遊戲內選的語言（選 EN 時是 PST）。
- 翻不到的字：`DISTRICT`、`WAVE`、`SEASON`、`Lv.` 等英文標籤，「缺少某狀態」的提示，信件與公告。
- `AbEvents*` 的 `prevDesc` 會被轉成大寫，連標籤裡的字母也是。

### 10. 官方檔案清單、語音表、資源檔（2026-11-18 補充）

取得了遊戲下載的資料與本體的 `resources.assets`（都不在版控裡），補上先前讀不到的部分，整理在 [10-assets.md](10-assets.md)：

- **官方檔案清單**（`RemoteLocalizeFileList.json`）：77 張表、1,259 個檔名。第 6 章推出來的「哪個檔在哪張表」全部正確。**KR 有 17 個檔不在清單裡，遊戲不會載入**（594 個字串，譯文已翻 581 個），最大的是 `StoryTheaterPersonality`、`StoryTheaterMirrorWorldStoryTitle`、`StoryTheaterMirrorWorld`，以及 `DungeonStartBuffs`、`DungeonStartBuffs_MD6`（只有 `_MD7` 會載入）。見 [01](01-custom-language.md)、[07](07-field-display.md) 第 6 節。
- **語音表**（`etc/VoiceTable.json`）：12 個前綴與 141 個語音 id，原意是限制哪些語音會帶出氣泡；但編譯出來的判斷永遠成立，這份表目前不擋任何句子。見 [05](05-battle-speech-bubble.md)。
- **下載網址**：官方文字是下載後以檔案讀取的（確認）。`RemoteLocalizeFileList.json`、語音表、RPG 檔案清單都有固定的網址，實際下載確認過。
- **啟動用清單**：五個檔，其中 `ErrorCodeMsgLocal`（16 句啟動階段的錯誤訊息）不在 `raw`，語言包沒有；內容和 `ErrorCodeMsg` 的同 id 相同，可以補。
- **樣式表**：31 個樣式。`highlight`、`upgradeHighlight` 是空的（黃字是程式換上去的）；`dkr`／`den`／`djp` 是該語言字型的發光材質，搭配語言包字型的效果還沒確認。
- **換行**：遊戲自動避頭尾，譯文不用為此手動換行。
- **靜態標籤**：1,862 個介面標籤直接綁定文字 id；估算後只有 2 個譯文可能超出框。
- 戰鬥氣泡、劇情對話框在場景檔裡，還沒有讀。

## 給網站檢查的建議，依嚴重程度

其中一部分已做成檢查（2026-11-15）：關鍵字誤連結、選擇事件頁數、同步等級比較、方括號文字、劇情的 `//`、多餘的大括號、`ChoiceEventEffect` 的正規表示式字元、字面的 `\n`、保留字、稱號換行旁的空格、罪孽型敵人的問號個數、但丁筆記的條列符號、ruby 寫法，共 13 個警告代碼，見 `docs/superpowers/specs/2026-11-15-game-text-checks-design.md`。2026-11-16 再加 `shared-line`（戰鬥氣泡與人格語音裡，同一句譯文對應不同的 KR）與 `cross-group`（同一句 KR 在另一個族群或欄位譯法不同）。其餘各項一部分由建置保證或由既有檢查涵蓋，另一部分刻意不做（理由見該文件 §2、§5）。

**會讓內容載不進來或錯位**

1. 每個檔是合法 JSON；檔名集合與 KR 相同。
2. 每筆條目的欄位集合、非字串的值、陣列長度與 KR 相同；id 集合相同、不重複。
3. 劇情檔的列數與 `id` 順序與 KR 相同；`model` 逐字相同；`teller`、`title` 是否為空相同。
4. `{n}` 的集合與 KR 相同，沒有其他 `{`、`}`；`ChoiceEventEffect*.content` 沒有 KR 沒有的半形 `( ) [ ] \ + * |`。

**會顯示出不該有的字**

5. `<ruby` 只出現在劇情 `content` 與 `BgmLyrics`，而且符合 `<ruby=[^>"]+>…</ruby>`。
6. 會做標籤處理的欄位裡，每個 `[xxx]` 都是 KR 同一欄位有的 id；不做標籤處理的欄位裡沒有 `[TabExplain]` 與技能標籤（KR 同一欄位有的除外）。
7. `<noparse>` 裡面沒有 `[` 與 `<`；`[TabExplain]` 前面不是空白。
8. 值不可以剛好是 `Unknown` 或 `Error`；劇情 `content` 沒有 KR 沒有的 `//`；沒有「反斜線＋n」。
9. 標籤名稱與 `<style>` 名稱都在 KR 同一欄位出現過；`<style="highlight">` 的寫法逐字相同。

**關鍵字對不對**

10. 對會處理的欄位，用 KR 與譯文各算出連結的 id 集合，列出譯文多出來的與少掉的（`method/kwsim.py diff`）。
11. `Bufs*.json` 與 `BattleKeywords*.json` 同 id 的名稱一致；狀態名稱沒有方括號、標籤、頭尾空白；KR 有 `excludeAutoLink` 的條目譯文也有；單字名稱與常用符號提醒要不要加。
12. `BattleUIText.json` 的 `cantIdentify` 等於 `<color=#ff0000>` ＋ `SkillTag.json` 的 `CantIdentify` 名稱 ＋ `</color>`。

**只影響呈現**

13. 選擇事件六種欄位的 `\n\n` 頁數與 KR 相同。
14. 技能、被動相鄰等級：KR 相同的行譯文也相同；行數相同。
15. 人格 `title`、E.G.O `name` 的 `\n` 前後沒有空白；罪孽型敵人名字的半形 `?` 個數與 KR 相同；但丁筆記 `\n-` 的數量相同。
16. 劇情對話超過 3 行字級會縮小（只能用字數粗估）；劇情字幕有 `<` 時不會自動拆段。
17. 戰鬥氣泡（`BattleSpeechBubbleDlg` 的 `dlg`、`PersonalityVoiceDlg` 裡 id 以 `battle` 開頭的 `dlg`）：頭尾沒有空白、沒有空行；長度超過 KR 與 JP 較長者的 1.3 倍或超過 111 字時提醒；KR 相同的變體（`-0N`）譯文也相同；同一句譯文不對應兩句不同的 KR。最後一點已做成檢查 `shared-line`，其餘還沒有（2026-11-16 補充，見 [05](05-battle-speech-bubble.md)）。

## 可信度與限制

- 結論來自**靜態分析**，沒有執行遊戲。每一章都分別標了「確認」（對照反組譯）與「推定」。
- 反編譯器的輸出不完全可靠。影響結論的判斷式（關鍵字的後接字元、`excludeAutoLink`、找不到 id 的行為、英文為底、ruby 的轉換條件、劇情列的配對）都另外對照了反組譯。
- 規則用資料驗證過：專案裡兩個在遊戲中確認過的關鍵字案例都重現；KR 官方擋關鍵字的 294 處裡，名稱後接字元符合規則的有 275 處（另有 9 處官方多擋了，其餘零星）。
- **讀不到的東西**：場景檔裡的設定（ruby 的大小與位置、各語言的字級、戰鬥氣泡的寬度與換行）、Unity 原生程式的行為（`JsonUtility` 對不嚴格 JSON 的容忍度、TextMeshPro 對未知標籤與缺字的處理）。
- 只分析了 Windows 版的這一個版本。遊戲更新後規則可能改變；enum 成員（哪些狀態 id 會自動連結）每次更新都會增加。
