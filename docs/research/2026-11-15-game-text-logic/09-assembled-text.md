# 程式拼接的句子與翻不到的字

2026-11-18。有些畫面上的字不是語言包裡的一整句，而是程式把幾段文字、符號、數值依固定順序接起來的。這一章列出這些拼法，以及語言包無論如何都翻不到的字。`{0}` 這類佔位符代入什麼，見 [08-placeholders.md](08-placeholders.md)。

依據：`Assembly-CSharp` 裡每一處直接呼叫字串組合函式的地方（3,930 個函式；去掉除錯訊息與資源路徑後讀了 1,040 組），加上全部 190 個直接讀遊戲內語言的地方與 19 個取語言的呼叫者（2026-11-12 版）。「確認」＝對照反編譯或反組譯；「推定」＝片段與符號是確認的，但先後順序或顯示位置是推的；位址是 RVA。

限制：

- 文字最後是經由虛擬呼叫指定給畫面元件的，所以「會不會真的顯示」只在反編譯結果看得到的地方算確認。
- prefab 裡相鄰擺放的標籤不在程式裡，看不到。
- RPG 模式自己的文字層只列出，沒有分析。

## 先講結論

- **順序由程式決定、譯者改不了的拼法**，最要注意的是：人格全名（稱號＋空格＋名字）、狀態名稱後接層數、標籤後接數值、日期。這些地方的譯文要寫成「放在那個位置讀起來通順」。
- **程式會自己加的符號不要再寫一次**：空格、冒號、方括號、半形括號、`%`、`+`、`x`、條列符號。
- **有一批字翻不到**：英文標籤（`DISTRICT`、`WAVE`、`SEASON`、`Lv.`……）、日期與時區、「缺少某狀態」的提示、信件與公告。
- **少數拼法依遊戲內選的語言而不同**（KR／EN／JP），中文語言包拿到的是所選語言的那一種。

## 7. 選擇事件

- **先後順序由譯者決定**：結果句是照範本裡 `{targets}`、`{conditions}`、`{reward}` 等記號的位置拼的。
- **接合的字元由程式決定**：
  - 多個角色名、多個屬性用 `", "`（半形逗號加空格）接。
  - 屬性條件後面會被加一個半形空格。
  - 需要的屬性之間是 `/`。
  - 修正值各行前面是 `"◆ "`。
- 所以 `ChoiceEventKeyword`、`ChoiceEventTarget` 的片段要寫成「放進範本那個位置讀起來通順」。
- 自訂語言頁數不夠時補上的 `...` 也是程式寫的。

## 8. 日期與時間

**全部由程式產生，語言包只管「剩餘時間」與「開放日期」幾個範本。**

| 項目 | 格式 |
|---|---|
| 一般日期 | `yyyy.MM.dd HH:mm`，後面加 `" (KST)"` 等時區 |
| 期間 | 兩個日期之間是 `" ~ "`、`" - "`、`"\n~ "` 或 `"\n- "` |
| 星期 | 英文三個字母大寫（`MON`） |
| 剩餘時間 | 只顯示一個單位：介面文字的「{0}天」、「{0}小時」或「{0}分鐘」其中之一 |
| 剩餘時間（天＋小時） | 把「{0}天」與「{0}小時」兩個字串**直接接在一起，中間沒有任何字元** |
| 開放日期 | 介面文字的範本，代入月、日、時區（順序由譯者決定） |

- **時區跟著遊戲內選的語言**（0x12A14C0，確認）：選 KR 是 KST，選 JP 是 JST，**選 EN 是 PST（少 8 小時，不算日光節約）**。有些地方時間固定用韓國時間，標示卻用這個函式，所以選 EN 時可能出現「韓國時間標成 PST」。
- 「剩餘時間」的幾個介面文字頭尾不要加空格或標點，否則接起來會多出來。
- 不要在顯示於日期旁邊的介面文字裡寫時區、星期或日期分隔符號。

## 9. 數字

- 大多數數字（層數、等級、花費）是程式自己組的：只有半形數字與負號，**沒有千分位**。
- 價格用 `#,##0`，千分位與小數點跟著作業系統的地區設定；幣別跟著遊戲內選的語言（韓元、美元、日圓）。
- 機率等百分比（`N4`、`N1`、`F1`）的小數點也跟著作業系統的地區設定；`%` 一律是程式加的。
- 羅馬數字用在研究等級與故事順序。
- 沒有找到遊戲自己設定地區的程式，所以分隔符號跟著作業系統（推定）。

## 10. 依遊戲內選的語言而不同的拼法

中文語言包沒有自己的分支，拿到的是玩家所選語言（KR／EN／JP）的那一種。

| 位置 | KR | EN | JP | 對中文的影響 |
|---|---|---|---|---|
| 單位頭上「缺少某狀態」的提示（0x100C770，確認） | 名稱＋`" 부족"` | `"Lack of "`＋名稱 | 名稱＋`" 不足"` | 前後綴翻不到；選 JP 時剛好像中文 |
| 時區 | KST | PST | JST | 見第 8 節 |
| 抽卡「截止」標籤的位置 | 日期後 | 日期前 | 日期後 | 見第 6 節 |
| 鐵道增益的「稱號＋名字」 | 有空格 | 有空格 | 沒有空格 | |

## 11. 套用在譯文上的文字轉換

| 轉換 | 套用的對象 | 對中文的影響 |
|---|---|---|
| 轉大寫 | 戰鬥的事件預兆橫幅（`AbEvents*` 的 `prevDesc`） | 譯文裡的英文字母變大寫，**標籤裡的字母也會**（`<color=#a16a3b>` 變成 `<COLOR=#A16A3B>`）；文字元件還認不認得大寫的標籤沒有確認 |
| 轉大寫（不變音） | 鏡牢入口的難度標籤 | 只影響英文字母 |
| 只留半形數字 | `StageChapterText` 的 `area` | 見第 4 節 |
| `\n` 換成空格 | 稱號、E.G.O 名稱在單行的地方 | 見第 1 節 |
| 去頭尾空白 | 鐵道增益的「稱號＋名字」 | |
| 去掉 `?` 並計數 | 罪孽型敵人的名字 | 半形 `?` 的個數有意義 |
| 截短加 `...` | 戰鬥中的技能名稱 | |
| 刪掉 `{一位數字}` | 技能說明 | 技能說明裡不能有 `{0}`～`{9}` |
| 以 `{`、`}` 切開並當正規表示式 | 選擇事件結果的範本 | 見 [04-other.md](04-other.md) |
| `(甲/乙)` 改寫成 `(甲)乙` | 個人檔案的問候句，只在選 KR 時 | 問候句裡不要寫半形括號加斜線 |
| 同步比較去掉數字後比對 | 技能說明 | 沒有影響 |
| 值轉大寫後等於 `UNKNOWN` | 名稱、`summary` | 被當成沒有資料 |

沒有找到套用在譯文上的複數或序數處理（鐵道的英文序數除外）。程式裡有一組挑韓文助詞的函式，但沒有人呼叫。

| `Unknown`、`UNKNOWN` | 語言包缺 id 時的預設值 |
| `위력 N - M` | 異想體圖鑑的技能威力（寫死的韓文） |
| 幾句韓文的除錯或佔位字串 | 語言包少了選項、資料缺漏、鏡牢的兩個側邊通知；會不會真的出現多半沒有確認 |
| `[ ERROR : {0} ]` | 網路與獎勵的錯誤彈窗 |
| 信件內文、公告、做成圖片的文字、製作名單 | 伺服器或圖片 |

## 給譯文的規則整理

1. 名稱類（人格 `title`、`name`、狀態名稱、E.G.O 名稱）頭尾不要有空格；狀態名稱不帶量詞；稱號與 E.G.O 名稱不自帶方括號。
2. 會被接上數值的介面文字（標籤）結尾不要有冒號或空格。
3. 「剩餘 {0}天」「{0}小時」這類字串頭尾不加空格或標點。
4. 不要自己寫 `%`、`+`、`x`、`Lv`、條列符號：程式會加。
5. `StageChapterText` 的 `area` 用半形數字。
6. 人格故事標題用的「的故事」寫成後綴；抽卡的「截止」選一個放在日期前後都通順的字。
7. 選擇事件的片段依範本裡記號的位置來寫；列舉用的分隔是半形逗號加空格，改不了。
8. `AbEvents*` 的 `prevDesc` 會轉大寫：避免在裡面寫英文與標籤。
9. 但丁筆記的分類名稱裡不要有半形空格，除非想在那裡斷行。

## 讀不到、沒有確認的部分

- 標成推定的拼法：片段與符號確定，先後順序沒有讀到暫存器層級。
- 抽卡三個日期標籤的先後是從程式讀的，哪一個是「截止」是從欄位順序與原文推的。
- prefab 裡相鄰的標籤與自動縮字。
- RPG 模式自己的格式化層。
- 事件預兆橫幅轉大寫之後，標籤還有沒有作用。
- 第 12 節裡幾句韓文字串會不會真的出現。
- 遊戲有沒有在啟動時設定地區（沒有在引擎的啟動碼裡找）。
