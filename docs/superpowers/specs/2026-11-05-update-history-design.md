# 網站「更新」頁：依 Release 查看譯文變動

## 目的

每次遊戲更新或規則改動後發布新的 Release，使用者要在網站上集中看到「這次語言包裡哪些單位變了、前後是什麼」，逐條確認譯文，不必一個個檔案去翻。每次 Release 都保留，網站上可以一路往回看任何一次。

## 目標

- 每個 Release 和它前一個 Release 比對，列出 KR 或譯文有變的單位，以及前後的 KR 與譯文。
- 比對結果在發布當下寫進 `tw`，一個 Release 一個檔，寫好的不再改；全部保留。
- 網站新增「更新」：Release 列表，以及單一 Release 的變動清單；清單有「卡片」與「表格」兩種顯示方式，使用者自己切換，網站記住選擇。
- 已經發過的 Release（`zh-TW-20261029.2` 到 `.7`、`zh-TW-20261105.1`）補上比對紀錄。

## 非目標

- 任選兩個 Release 比對；只比相鄰的兩個。
- 顯示當時的 JP／EN。比對紀錄只存 KR 與譯文；JP／EN 顯示的是目前的版本。
- 單一單位跨所有 Release 的完整歷程頁。
- 在這一頁確認或處理項目（審核頁與 `lct accept` 的工作不搬過來）。

## 反目標（做到了也算失敗）

- KR 與譯文都沒變、只是換了位置的單位被列出來。
- 首頁、檔案頁、搜尋、審核頁因此變慢：比對資料只在打開該 Release 時下載。
- Release 發布之後，它的比對紀錄被改寫。

## 做法比較

| 做法 | 內容 | 取捨 |
|---|---|---|
| A. plan 當下記錄 | `lct plan` 比對新舊快照時，把每個變動寫下來，翻完再補新譯文 | 只抓得到遊戲更新帶來的變動；規則改動重翻、人工調整、上週沒翻完這週補翻，得在每個寫入點另外記錄 |
| B. 部署網站時從 git 歷史算 | `lct site` 每次部署都用 git 比對每一對相鄰 Release | 不改發布流程；但每次部署都重算，Release 越多越慢，pages 也要抓完整歷史；結果不固定在 `tw` |
| **C. 發布時和前一個 Release 比對，存進 `tw`（採用）** | `lct publish` 準備 Release 時，把語言包和前一個 Release 比對，結果寫進同一個 `tw` commit | 不管變動的原因是什麼，語言包裡變了的都抓得到；結果在發布當下固定下來 |

使用者選了「存下來、全部保留」（A 或 C 的方向），並同意以「和前一個 Release 比」為單位（C）。

## 名詞

- **單位**：語言包裡的一個字串（檔案 + JSON pointer），和網站檔案頁的一列相同。
- **前一個 Release**：照 `publish.LastRelease` 的排序（日期，同日比 `.N`），排在這個 Release 前面的那一個。`zh-TW-20261105.1` 的前一個是 `zh-TW-20261029.7`。
- **一個 Release 的狀態**：它的 tag 指向的 `tw` commit。那個 commit 的 `.meta/build.json` 記著 raw tag 與 rules commit；KR 取自 `raw` 在那個 raw tag 的檔案，譯文取自那個 commit 的 `LimbusCompany_Data/`（打包出的字串，和網站檔案頁的 `zh` 相同），來源（origin）取自那個 commit 的 `.meta/units/`（沒有紀錄的單位是 `stand-in`，同網站）。

## 決定的部分

### 比對

把前一個 Release 的狀態（舊）和這個 Release 的狀態（新）逐檔比對。

- 舊單位和新單位的對應，用 `lct plan` 在兩個 KR 快照之間用的同一套對應（`internal/plan` 的 Transition／`align.AlignVersions`），不另做一套：有 id 的項目按 id 對應，其他照 plan 的做法。所以「只是換位置、KR 沒變」的單位有對應，不算變動。兩個 Release 的 raw tag 相同時，KR 一樣，按 pointer 對應即可。
- 按 id 對應時，同一個 id 的字串變了就是「KR 修改」，即使看起來像整段往後移。例：`LobbyBGM-29.json` 在 raw-20261105 插入一首曲子，id 200342–200344 的曲名各自換成另一首的名字；遊戲裡這些 id 的名字確實變了，譯文也跟著變，所以列為 KR 修改（這是 plan 的 14 個 KR 修改中的 3 個）。（我的決定：先前在對話裡我把這個例子說成「只是換位置、不該列出」，那是我看錯了 diff；照 plan 的對應，這三個是真的修改。）
- 每個單位歸成一種變動，或不列出：

| 種類 | 代碼 | 條件 | 顯示的前後 |
|---|---|---|---|
| 新增 | `new` | 新版有、舊版沒有對應 | 新 KR、新譯文 |
| KR 修改 | `kr-changed` | 有對應，KR 不同 | 舊／新 KR、舊／新譯文 |
| 刪除 | `deleted` | 舊版有、新版沒有對應 | 舊 KR、舊譯文 |
| 只有譯文改變 | `zh-changed` | 有對應，KR 相同，譯文不同 | KR（一份）、舊／新譯文 |
| （不列） | | 有對應，KR 與譯文都相同（包括只是換位置的） | |

- 每個「只有譯文改變」標原因：新的來源是 `human` 為「人工調整」；舊的是 `stand-in`（之前沒有譯文，暫用英文或 KR）為「補翻」；其他為「重翻」。
- 每個單位標「不需翻譯」（新的、或刪除時舊的來源是 `copy`，例：ID、數字），網站預設隱藏。
- 比對看的是打包出的字串，所以結果就是玩家拿到的語言包的差異。

### 比對紀錄檔

- 位置：`tw` 的 `.meta/history/<Release tag>.json`，例：`.meta/history/zh-TW-20261105.1.json`。一個 Release 一個檔。
- 內容：一個 JSON 物件。
  - 表頭：`tag`、`prev_tag`、`released_at`（這個 Release 的 `tw` commit 的時間）、`raw_tag`、`prev_raw_tag`、`rules_commit`、`prev_rules_commit`，以及各種變動的數量（另計其中不需翻譯的數量）。
  - 表頭另有「其他檔案」：語言包裡字串檔以外、內容有變的檔案路徑（例：`Info/LICENSE-CONTENT`、字型、`config.json`），不含每次建置都會變的 `Info/version.json`。例：`zh-TW-20261029.2` 和 `.1` 相比只有 `Info/LICENSE-CONTENT` 變了，它的紀錄沒有任何單位，但列出這個檔。（我的決定：舊的紀錄只寫一次，現在不留這個欄位，之後就補不回來。）
  - `entries`：每個變動一筆，含檔案、欄位、pointer（新的；刪除的是舊的）、種類、舊／新 KR、舊／新譯文、舊／新來源、是否不需翻譯、原因（只有譯文改變才有）。不存的那一側（例：新增沒有舊的）省略。
  - 排序：檔案依網站目錄的順序，同一檔依新版文件順序，刪除的放在它在舊版的位置附近（細節留給實作）。
- 大小：每筆約 400 bytes。這次（raw-20261105）約 50 KB；大型劇情更新一次 1–4 MB。寫好不再改，git 只存一次。

### 何時寫入

- `lct publish` 準備的 commit 的語言包和前一個 Release 不同（也就是這次會發 Release）時，寫這個 Release tag 的比對紀錄，放進同一個 `build:` commit。比對紀錄只在 `.meta/` 底下，不影響 `SamePack` 對語言包的判斷。
- Release 沒建成（例：`gh release create` 失敗）時，下一次執行用的仍是同一個 tag（`ReleaseTag` 的規則），比對紀錄跟著重寫；Release 建成之後，它的比對紀錄不再改寫。
- 補齊：`lct publish` 每次也檢查所有已存在的 Release tag，除了最早的那一個，缺比對紀錄的就和它前一個 Release 比對並寫入，同樣放進那個 commit。只讀 git 物件（tag、tree、blob），不需要 checkout 舊版。已發的 `zh-TW-20261029.2`–`.7`、`zh-TW-20261105.1` 在下一次 pipeline 不是 idle 的執行時補上。
- 最早的 Release（`zh-TW-20261029.1`）沒有前一個，不寫比對紀錄；網站仍列出它，標「第一版」。
- 狀態只經由 `lct` 修改、`tw` 只由 CI 寫入的規則不變。

### `lct site` 匯出

- 讀 `tw` worktree 的 `.meta/history/*.json`，寫：
  - `data/updates/index.json`：所有 Release（包括沒有比對紀錄的第一版）的表頭與數量，新的在前。Release 的清單與日期以 tag 為準。
  - `data/updates/<tag>.json`：該 Release 的 `entries`。
- `meta.json` 不放比對資料，首頁不需要多下載。

### 網站

- **入口**：頂端列「審核」旁邊（左邊）新增「更新」。
- **路由**：`#/u` 是 Release 列表；`#/u/<tag>` 是單一 Release，查詢參數放篩選（種類、來源、檔案、是否顯示不需翻譯的）。
- **Release 列表**：新的在上。每列：tag、日期、「比對 <前一個 tag>」，以及類別標籤：raw tag 和前一個不同是「遊戲更新 <raw tag>」，相同是「重建」；接著是各種變動的數量（不含不需翻譯的），有「其他檔案」時另一個標籤寫出檔案數。沒有任何單位變動、只有其他檔案變的，也照樣列出。第一版只列 tag 與日期，標「第一版，沒有可比對的上一版」。
- **單一 Release**：
  - 表頭：tag、日期、類別、比對的 tag、變動的檔案數；有「其他檔案」時列出它們的路徑。
  - 篩選：
    - 種類：四個可開關的標籤，附數量。
    - 來源：下拉。
    - 檔案：下拉。
    - 「隱藏不需翻譯的單位」：預設勾選，旁邊寫出數量。
  - 顯示方式「卡片｜表格」：存在使用者設定（和語言勾選一樣存在瀏覽器），下次打開沿用。
  - 依檔案分組，組名是檔案路徑。
- **卡片**：一個單位一張卡。
  - 上方：種類標籤、欄位與 pointer、來源（舊 → 新），「只有譯文改變」另有原因標籤。
  - 內容：KR 舊在上、新在下，再來是譯文舊在上、新在下；改動的部分用審核頁現有的差異標色（`variantDiff`／`DiffText`）。新增只有新的，刪除只有舊的，只有譯文改變的 KR 只顯示一份。
  - 「JP／EN（目前的）」預設收起，點開才讀取該檔的網站資料（`data/files/…`）並顯示。
  - 「在檔案中開啟」連到 `#/f/<檔案>?u=<pointer>`；刪除的單位沒有這個連結。
- **表格**：一列一個單位，欄位：欄位、種類、KR、TW、來源。
  - 格子裡舊的（灰色）在上、新的在下，有差異標色。
  - 長句子只顯示前幾行，點那一列展開全文。
  - 手機寬度時表格在自己的容器裡左右捲動，頁面本身不左右捲動。
- **沿用現有設定**：
  - 右上的語言勾選決定顯示哪些語言（TW 永遠顯示；KR 未勾時不顯示 KR 的前後；JP／EN 未勾時不提供展開）。
  - 「顯示原始標籤」照常切換譯文與原文的標籤顯示，差異標色也跟著切換。
- **大量資料**：一個 Release 有上萬筆時仍可捲動與篩選，不卡頓（可沿用檔案頁的虛擬捲動）。

## 限制

- 遵守 `CLAUDE.md`：
  - 規則只在 `guides/`、`glossary/`、`rules/`。
  - 狀態只經由 `lct` 修改。
  - `raw`、`tw`、Release 只由 CI 寫入。
  - 所有 `lct` 指令支援 `--json`。
  - 提交前 `go vet ./... && go test ./...` 通過。
  - 動到 `site/` 時 `npm test && npm run build` 與 `npm run typecheck` 通過。
- `pipeline.yml` 已經抓 `raw`、`tw` 的完整歷史與所有 tag，`lct publish` 讀得到舊 Release 的物件；`pages.yml` 只需要 `tw` worktree 目前的檔案。
- 網站的手機寬度、深色模式、鍵盤操作沿用現有做法。
- README 說明新增的「更新」頁與 `.meta/history/`。

## 留給實作者

- 比對時哪些檔案需要逐單位比（例：只比 raw 兩個 tag 之間有變的 KR 檔，加上兩個 `tw` commit 之間有變的語言包檔，及其來源紀錄有變的檔）。
- 比對紀錄 JSON 的欄位名稱與網站資料的格式（可以和比對紀錄相同，或精簡）。
- 刪除的單位在清單中的確切位置。
- 表格收合的行數、卡片與表格的細部樣式（以樣式草圖 https://claude.ai/artifact/GDGH4kiLW8zQHeZ58GrHcy 為準）。
- 篩選參數的名稱。

## 驗收

- 在真實資料上，`zh-TW-20261105.1` 對 `zh-TW-20261029.7`：
  - 新增、KR 修改、刪除的數量是 104／14／12，和 plan 一致（實作前已用 plan 的對應加打包字串的比較在真實資料上試算過，結果相同）。
  - `LobbyBGM-29.json` 的 `/dataList/39`、`/40`、`/41` 的 `name` 列為 KR 修改。
  - `EGOgift_MirrorDungeon.json` 的 `/dataList/277/desc` 列為 KR 修改，前後譯文是 Paratranz 的「+1」版與 Claude 的「+2」版。
- 補齊後 `zh-TW-20261029.2`–`.7` 各有比對紀錄；再執行一次不產生任何改動。試算的單位數供對照：`.2` 0（只有 `Info/LICENSE-CONTENT`）、`.3` 2、`.4` 132、`.5` 596、`.6` 53、`.7` 6，全部是「只有譯文改變」。
- 網站：
  - 「更新」列表列出全部 8 個 Release。
  - 卡片與表格可切換，重新整理後保持。
  - 篩選與「在檔案中開啟」可用。
  - 手機寬度不出現整頁左右捲動。
